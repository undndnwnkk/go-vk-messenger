# 0004. Frontend API client generated at build time

Status: accepted (2026-11-18)

## Context

API types must come from `backend/api/openapi.yaml` and never be hand-written.
A committed generated file drifts from the spec and fills diffs with noise.

## Decision

- `openapi-typescript` generates `frontend/src/api/schema.gen.ts`. The file is
  git-ignored and is regenerated by the `dev`, `build`, `typecheck`, `test` and
  `lint` scripts (npm `pre*` hooks), so a spec change that breaks the frontend
  fails typecheck immediately.
- `openapi-fetch` is the runtime client: about 6 kB, typed paths, params and bodies,
  no codegen of functions.
- `unwrap()` turns every non-2xx response into an `ApiError` with `status`, `code`
  and `message` from the backend's `{"error":{"code","message"}}` body. A body in
  another shape becomes `unknown_error`, a failed fetch becomes `network_error`
  with status 0. UI code branches on `code`, never on `message`.
- TanStack Query does not retry 4xx errors.

## Consequences

- A fresh clone needs `npm install` and any `npm run` script before the editor
  sees the types.
- Request and response shapes are checked against the spec at compile time, but
  values are not validated at runtime.
